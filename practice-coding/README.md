# practice-coding

Practice problems for the OpenAI software engineer interview. Each file in
`src/practice_coding/` opens with a problem statement in parts, plus links to
where it was reported.

## About the loop (as reported, not official)

- Recruiter screen → technical phone screen (coding or system design) → virtual
  onsite of 4–5 rounds; some senior roles add a paid 48-hour work trial.
- 45–60 minute rounds in CoderPad. The problem comes in parts, and requirements
  are added while you work.
- Mostly "build a small working system" problems; LeetCode-medium questions
  still appear.
- Grading reportedly covers design, code quality, performance, and test coverage.
- Questions that have circulated for a few months tend to rotate out.

## Problems reported by candidates

| File | Problem |
|---|---|
| `resumable_iterator.py` | Iterator with save/restore of position; tests first |
| `versioned_key_value_store.py` | Time-based key-value store |
| `rate_limiter.py` | Fixed window, sliding window, token bucket |
| `in_memory_sql_db.py` | SQL-like `select` with `where` / `order_by` |
| `spreadsheet.py` | Formula cells, cycle detection, O(1) reads |
| `credit_tracker.py` | Credit balances with expiration |
| `webhook_dispatcher.py` | Delivery with retries and a dead-letter queue |
| `web_crawler.py` | Same-domain crawl, then concurrent |
| `one_nn.py` | 1-NN / KNN classifier (ML-adjacent roles) |
